# CI audit, 2026-09-26

Scope: Claudex at `a8d4d21` with local, uncommitted CI edits. This is dated
evidence, not proof that the edits passed hosted CI.

## Evidence and decisions

- Audited all six GitHub Actions workflows, the required branch statuses,
  native platform coverage, release checks, and local test entry points.
- The repository was public when checked. [GitHub billing guidance](https://docs.github.com/en/actions/concepts/billing-and-usage)
  says standard hosted runners are free for public repositories. The standard
  GitHub runner choice and Blacksmith exception are recorded in
  `docs/development.md`.
- The [2026-09-23 Blacksmith run](https://github.com/BeamoTech/Claudex/actions/runs/35803572683)
  waited nearly three hours for macOS. The
  [2026-09-26 GitHub run](https://github.com/BeamoTech/Claudex/actions/runs/36283161738)
  started macOS within seconds and completed the matrix in about 16 minutes.
  Those are dated observations, not a guarantee of future queue times.
- On that GitHub run, the macOS Bash suite took 15 minutes 29 seconds; checkout
  took two seconds and the following PowerShell test took 30 seconds. The Bash
  suite is the wall time bottleneck.
- The [2026-07-22 release run](https://github.com/BeamoTech/Claudex/actions/runs/29904821169)
  spent about 15 minutes in its macOS release gate, then 24 seconds in the
  publishing job. The matching [installer verification](https://github.com/BeamoTech/Claudex/actions/runs/29905853826)
  resolved the expected version in four seconds. These short jobs do not
  justify changing release ordering or public installation coverage.
- Among the latest 100 Actions runs checked on 2026-09-26, three older pull
  request test matrices were canceled during rapid source updates in August.
  The existing main test concurrency is doing useful work; keep it.
- The latest inspected [CodeQL job](https://github.com/BeamoTech/Claudex/actions/runs/36283161748)
  took 66 seconds. The inspected [dependency review](https://github.com/BeamoTech/Claudex/actions/runs/35924267214)
  took four seconds and [labeler](https://github.com/BeamoTech/Claudex/actions/runs/35924267290)
  took eight seconds. Their security and labeling coverage is worth retaining.
- `package-lock.json` lists only the root package and no external npm packages.
  There is no dependency installation in the test matrix to accelerate with an
  npm cache. The release builder uses repository files and local staging, so
  an archive cache would risk stale source and cost more coordination.
- Local edits cancel superseded dependency review and labeler runs, remove a
  redundant labeler event, and avoid a second apt index fetch in the legacy
  Ubuntu test.
- [GitHub reusable workflow guidance](https://docs.github.com/en/actions/reference/workflows-and-actions/reusing-workflow-configurations)
  says a called workflow inherits the caller's `github` context. The test
  workflow now uses the release call's supplied `ref` to give that gate a
  distinct run group; direct branch and pull request runs still cancel stale
  checks. The old `github.event_name == 'workflow_call'` condition could not
  identify this call.
- Required statuses, native macOS, Ubuntu, and Windows suites, CodeQL,
  dependency review, minimum Node coverage, and release gates remain present.
- Branch protection still requires `macos-15`, `ubuntu-24.04`, `windows-2025`,
  `ubuntu-20.04-managed-node`, `package-artifacts`, `CodeQL`, and
  `Dependency review` with strict up to date checking. The repository was
  confirmed public again during this local review.

## Local verification

- The original `test.zsh` passed on macOS in 554 seconds against the edited
  source. A trial that skipped some skill discovery passed twice in 565 and
  626 seconds, so it was removed: these runs did not show a speed benefit.
- A temporary profile of the passing suite measured about 153 seconds in proxy
  and model checks, 111 seconds in composite launch checks, and 166 seconds in
  update lock and detached update checks. These retain race and provider
  boundary coverage.
- A later timing profile exposed a test race: the background status refresh
  helper had only two seconds to publish its log before the Unix test read it.
  The Unix and Windows suites now wait up to 20 seconds for four complete
  lines, exiting early on the normal path. A deliberately delayed Unix helper
  and the PowerShell fixture write passed locally. The exact edited `test.zsh`
  suite passed in 676 seconds after the final fixture edits; native Windows
  verification is still pending.
- Every preceding component of `test.sh` passed separately, including watcher,
  authentication lock, Windows source parity, and test driver regressions.
- `npm test`, macOS PowerShell self update lock regressions, `actionlint`, Bash
  syntax checks, Markdown checks, `git diff --check`, and release archive
  reproducibility and extracted install checks passed.
- The agent, development, and contributor syntax commands now use
  `bash -n test.zsh`, matching the script shebang and the shell that CI runs.
- The Ubuntu 20.04 container job and native Windows suite require hosted
  verification. At the time of this local audit, no hosted CI had been run or
  triggered under the user's restriction.
- Parallelizing the short, isolated shell regressions in `test.sh` would save
  little compared with the macOS launcher suite and would complicate its
  early failure test driver. Keep their sequential order until measured evidence
  justifies a change.
